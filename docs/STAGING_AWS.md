# Staging on AWS (Dokploy)

Runbook for the multi-tenant staging installation. Everything is done
through the Dokploy panel or its API; no SSH. Background:
[INSTALL.md](INSTALL.md) (host layout, edge modes), day-2 work:
[OPERATIONS.md](OPERATIONS.md). No secret belongs in this file or the
repository.

## 1. What is already there

| Item | Value |
|---|---|
| Server | EC2 eu-central-1, Ubuntu 24.04, 8 GB / 2 vCPU, Elastic IP `35.156.227.62` |
| Dokploy | `https://dokploy.messora.tech`; its Traefik owns ports 80/443 |
| DNS (name.com) | `messora.tech` A → `35.156.227.62`, `*.messora.tech` A → `35.156.227.62` |
| S3 | `messora-media-575500997783` (private), `messora-public-575500997783` (public through CloudFront, pending AWS verification; `cdn.messora.tech` will be a CNAME to it) |
| Credentials for S3 | EC2 instance role with read/write on both buckets; IMDSv2 hop limit 2, so containers reach it |
| Mail | Resend SMTP `smtp.resend.com:465`, TLS, user `resend` |

Resulting addresses: companies `https://<slug>.messora.tech`, platform
admin `https://admin.messora.tech`, sign-up `https://app.messora.tech`,
webhooks `https://hooks.messora.tech/meta/<key>`.

## 2. What the owner provides

| Secret | Where it goes | Notes |
|---|---|---|
| Dokploy API key | the operator's environment (`DOKPLOY_API_KEY`) | Dokploy → Settings → Profile → API keys; already in the Keychain |
| name.com API user name + token | **Traefik's** environment only | name.com → Account → Security → API token (production). It can edit every DNS record of the account |
| Resend API key | stack env `SMTP_PASSWORD` | sending domain `messora.tech` verified in Resend (SPF/DKIM records at name.com) |
| Git access for Dokploy | Dokploy → Git (GitHub app or SSH key) | the repository is private |

Generated by the operator (store each in the Keychain as
`messora-staging/<NAME>` before deploying):

```bash
openssl rand -base64 32                               # APP_ENCRYPTION_KEY
for n in BFF_SHARED_SECRET POSTGRES_PASSWORD POSTGRES_APP_PASSWORD POSTGRES_SYSTEM_PASSWORD \
         REDIS_PASSWORD CENTRIFUGO_API_KEY CENTRIFUGO_HMAC_SECRET; do
  printf '%s=%s\n' "$n" "$(openssl rand -base64 36 | tr '+/' '-_' | tr -d '=\n')"
done
```

`APP_ENCRYPTION_KEY` decrypts every company's stored credentials (Meta
tokens, TOTP secrets, webhook secrets): losing it loses them, and the
nightly dumps deliberately do not contain it.

## 3. Traefik (once)

All calls: `-H "x-api-key: $DOKPLOY_API_KEY" -H 'Content-Type: application/json'`
against `https://dokploy.messora.tech/api/`. Endpoint names are those of
Dokploy's API at the time of writing; check them on
`https://dokploy.messora.tech/swagger` first. Each step can also be done
in the panel (Settings → Traefik).

1. **Environment** (`settings.readTraefikEnv` / `settings.writeTraefikEnv`):
   keep what is there and add

   ```dotenv
   NAMECOM_USERNAME=<name.com user>
   NAMECOM_API_TOKEN=<name.com token>
   NAMECOM_SERVER=https://api.name.com
   ```

2. **Static configuration** (`settings.readTraefikConfig` /
   `settings.updateTraefikConfig`, the main `traefik.yml`): keep Dokploy's
   entry points, providers and its `letsencrypt` HTTP-01 resolver, and add:

   ```yaml
   certificatesResolvers:
     letsencrypt-dns:
       acme:
         email: ops@messora.tech
         storage: /etc/dokploy/traefik/dynamic/acme-dns.json
         dnsChallenge:
           provider: namedotcom
           resolvers: ["1.1.1.1:53", "8.8.8.8:53"]
   providers:
     http:
       endpoint: "http://messora-staging-edge:8081/internal/edge/traefik"
       pollInterval: "30s"
   ```

   (`messora-staging` is `PROXY_ROUTER` below; the stack's Caddy has the
   alias `<PROXY_ROUTER>-edge` on `dokploy-network`. Until the stack runs,
   Traefik logs that the provider endpoint is unreachable; that is
   harmless.)

3. **Reload** (`settings.reloadTraefik`). Traefik must still answer
   `https://dokploy.messora.tech` afterwards; if it does not, restore the
   previous `traefik.yml` from the read in step 2.

## 4. The compose application

```bash
API=https://dokploy.messora.tech/api
h=(-H "x-api-key: $DOKPLOY_API_KEY" -H 'Content-Type: application/json')

# Project and its environment (projects have environments in current Dokploy).
curl -s "${h[@]}" "$API/project.create" -d '{"name":"messora-staging","description":"Messora multi-tenant staging"}'
curl -s "${h[@]}" "$API/project.all"            # → projectId, environments[].environmentId

curl -s "${h[@]}" "$API/compose.create" \
  -d '{"name":"messora","appName":"messora-staging","environmentId":"<environmentId>","composeType":"docker-compose"}'
# → composeId
```

Source and compose path (`compose.update`): the repository, the branch or
tag to stage (`phase-17` until the release), and

```json
{ "composeId": "<composeId>", "composePath": "./docker-compose.dokploy.yml", "env": "<the environment below>" }
```

plus the source fields of the chosen Git provider (`sourceType`
`github` with `repository`/`owner`/`branch`/`githubId`, or `git` with
`customGitUrl`/`customGitBranch`/`customGitSSHKeyId`). Do **not** add
domains to the application: routers come from the `caddy` labels.

**Environment:** `deployments/dokploy/messora.env.example` with:

```dotenv
MESSORA_VERSION=staging
TENANT_BASE_DOMAIN=messora.tech
PUBLIC_APP_URL=https://app.messora.tech
HOOKS_PUBLIC_URL=https://hooks.messora.tech
EDGE_MODE=proxy
PROXY_ROUTER=messora-staging
TRUSTED_PROXIES=<subnet of dokploy-network>
# the eight secrets from §2
STORAGE_DRIVER=s3
S3_REGION=eu-central-1
S3_BUCKET_PRIVATE=messora-media-575500997783
S3_BUCKET_PUBLIC=messora-public-575500997783
SMTP_PASSWORD=<Resend API key>
SMTP_FROM=Messora <no-reply@messora.tech>
COMPOSE_PROFILES=backup
BACKUP_S3_BUCKET=messora-media-575500997783
```

`TRUSTED_PROXIES`: the subnet of `dokploy-network` (Dokploy's web terminal:
`docker network inspect dokploy-network -f '{{range .IPAM.Config}}{{.Subnet}} {{end}}'`).
If it cannot be read yet, leave the line out: the default `private_ranges`
works and only weakens client addresses against other applications on the
same Dokploy host; set it before real customers arrive.

**Deploy** (`compose.deploy` with `{"composeId":"<composeId>"}`) and follow
the deployment log (`deployment.allByCompose`). The first build takes a few
minutes (Go, Next.js and the Caddy build with the name.com module). Order:
`messora-init` → postgres/redis/centrifugo healthy → `messora-migrate`
(exit 0) → api, worker, scheduler → web → caddy (and backup).

## 5. After the first deploy

1. **Certificates.** Traefik's log shows the order for `messora.tech` +
   `*.messora.tech` through `letsencrypt-dns`. Then:

   ```bash
   curl -sI https://app.messora.tech/login      # 200, valid certificate
   curl -sI https://admin.messora.tech/login    # 200
   curl -s -o /dev/null -w '%{http_code}\n' https://hooks.messora.tech/meta/unknown     # 404 (API)
   curl -s -o /dev/null -w '%{http_code}\n' https://hooks.messora.tech/                 # 404 (edge)
   curl -s https://nobody.messora.tech/api/v1/system/status  # TENANT_NOT_FOUND
   curl -sI http://app.messora.tech/login       # 301/308 to https
   ```

2. **First platform admin.** The `messora-migrate` log has the bootstrap
   link (`https://admin.messora.tech/bootstrap?token=…`, 24 h, single use).
   Or, in Dokploy's terminal of the `messora-api` container:
   `printf '%s\n' '<password>' | messora admin create --email <owner e-mail> --name "<name>" --password-stdin`.
   Two-factor enrolment follows at the first sign-in.
3. **Backups.** `BACKUP_RUN_ON_START=true` made one dump right after the
   deploy; the `backup` container log names the S3 key. Add the lifecycle
   rule of [OPERATIONS.md](OPERATIONS.md#2-backups) (30 days) once.
4. **A company and a custom domain** (end-to-end check of the edge): open a
   company in the admin panel, sign in on `https://<slug>.messora.tech`,
   see "Live". For a custom domain, CNAME it to `custom.messora.tech`,
   verify it in the admin panel, wait one provider poll (30 s), open it
   over HTTPS.
5. **CloudFront**, once AWS verifies the account: CNAME `cdn.messora.tech`
   to the distribution, add `PUBLIC_ASSET_BASE_URL=https://cdn.messora.tech`
   to the environment, redeploy.

## 6. Later deploys and rollback

Redeploy with the new branch or tag (`compose.update` + `compose.deploy`)
following [OPERATIONS.md §3](OPERATIONS.md#3-upgrades): dump first
(`docker compose run --rm backup once`), migrations run before the
services. Roll back by deploying the previous tag; if a migration must be
undone, restore the dump taken before the deploy (OPERATIONS.md §2).

## 7. Edge mode without Dokploy

If the server ever runs without Dokploy, the same stack terminates TLS
itself: `EDGE_MODE=caddy`, `NAMECOM_USERNAME`, `NAMECOM_API_TOKEN` in the
stack's environment, compose file `docker-compose.yml` (ports 80/443).
Custom domains then use on-demand TLS behind the API's ask endpoint.
